# SPEC: `mythos report` - the human window over a run

Owner of judgment: Prime. This spec is binding; deviations need a BLOCKED line, not improvisation.

## What it is

A new Rust subcommand `mythos report --run-dir <dir>` that renders ONE self-contained HTML page (`<run-dir>/state/report.html`) a non-technical founder can read to answer: "what did the agents actually do, and how much of it is proven?"

## Files

1. NEW `mythos-compiler/src/compiler/report.rs`
   - `pub fn render_report(packet: &NextPassPacket, receipts: &[ReceiptRecord], gate: Option<&GateReport>) -> String` - pure function, unit-testable.
   - `pub fn generate_report(run_dir: &Path) -> Result<PathBuf, Box<dyn std::error::Error>>` - loads `state/next_pass_packet.json`, receipts via `crate::compiler::receipts::load_verified_receipts`, optional `state/gate-report.json` (shape: `{ "ok": bool, "errors": [String], "warnings": [String] }` - define a small `GateReport` deserialize struct in report.rs with serde defaults, tolerate missing/extra fields), writes `state/report.html`, returns the path.
   - Register `pub mod report;` in `src/compiler/mod.rs`.
2. EDIT `mythos-compiler/src/bin/mythos.rs`: add `report` command (parse `--run-dir` with the existing `parse_run_dir`, call `generate_report`, print the output path). Add one line to the help text.

## The page (top to bottom)

1. **Header**: objective text, run_id, pass_id, generated timestamp string taken from the packet/receipts (do NOT call system time in `render_report` - determinism; `generate_report` may stamp using the latest receipt/evidence observed_at it finds, or omit).
2. **Verdict banner**: gate report present and ok -> green "GATE PASSED"; present and not ok -> red "GATE FAILED" + each error on its own line; absent -> amber "GATE NOT RECORDED - run mythos-skill gate".
3. **Attestation scorecard** (the campaign number): counts + percentage. Definitions:
   - attested = trusted_facts with attestation == "attested"
   - verifier = trusted_facts with attestation == "verifier"
   - refuted = contradictions whose id starts with "con:receipt:"
   - asserted = evidence records whose kind is NOT in {objective, subagent-session, codex-synthesis, blocker, unstructured, receipt} and whose id has no corresponding "fact:<id>" in trusted_facts
   - unstructured = evidence kind == "unstructured"
   - Coverage = attested / (attested + verifier + asserted), rendered as "N% attested" with the raw counts beside it; guard division by zero (0 claims -> "no substantive claims").
4. **Refutations** (only if any): red panel, one row per con:receipt:* contradiction, full summary text.
5. **Receipts table**: id, label (or "-"), command joined with spaces, exit code (0 green / nonzero red), duration_ms, links `<a href="../receipts/artifacts/<hash>.txt">stdout</a>` / stderr (relative links; page lives in state/).
6. **Trusted facts**: table with tier badge (attested = green badge, verifier = blue badge), statement, source_ids joined.
7. **Evidence by lane**: group by `lane` (fallback "(no lane)"), each record: id, kind, summary, grey "asserted" badge when unpromoted, orange "demoted" badge + the warnings list when provenance_warnings is non-empty, purple "unstructured" badge for unstructured kind.
8. **Verifier findings**: id, status (passed green / failed red / other amber), score, summary, finding_kind if present.
9. Footer: "Generated by mythos report - Receipts engine".

## Hard requirements

- **Escape EVERYTHING that came from agents or files**: write `fn html_escape(s: &str) -> String` replacing `& < > " '`. Every summary, statement, id, label, command, error string goes through it. There WILL be an XSS test throwing `<script>alert(1)</script>` at you.
- Self-contained: ONE inline `<style>` block, system font stack, no external URLs, **no `<script>` tags at all**.
- Simple, readable, founder-grade: max-width ~960px, badges as rounded inline-blocks, tables with border-collapse and zebra rows. Both light-ish default is fine; do not over-design.
- No new crate dependencies. No `Date::now`-style calls inside `render_report`.
- `cargo fmt` clean; `cargo test` green including YOUR new unit tests in report.rs:
  - html_escape escapes all five characters
  - a packet containing `<script>` in a summary renders with `&lt;script&gt;` and the raw sequence `<script` does NOT appear in the HTML
  - a con:receipt:* contradiction renders inside the refutations panel
  - receipt row renders exit code and label
  - coverage math: 2 attested + 1 verifier + 1 asserted -> "50% attested" (2/4)
- Do not touch any other file beyond the three named above.

## Definition of done for your lane

cargo fmt + cargo test green locally (cite the label `test:cargo-suite` in your verifier record - Prime re-runs it and a mismatch refutes you), then generate a report against the run dir you were given and confirm the file exists (cite label `command:report-smoke`).
